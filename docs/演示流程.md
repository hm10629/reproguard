# 演示流程

本文给出可现场演示的三条路径，以及每条路径的输入、输出、观察点和失败降级方式。

## 0. 前置准备

在项目目录下操作（以下路径仅为本机示例，其他电脑请替换为实际克隆目录）：

```powershell
cd path\to\reproguard
```

先确认当前环境的 Python 解释器：

```powershell
python --version
```

安装依赖（仅 PDF 输入需要，TXT/Markdown 不装也能跑）：

```powershell
python -m pip install -r requirements.txt
```

### 演示用的样例是什么

本文所有命令都使用 `data/examples/incomplete-ml-project/`。这是**自造固定样例**，用于验证规则本身是否写对。

> 它不是真实论文项目。演示时不要称它为「真实论文」或「真实评测集」。真实公开项目评测使用 `jaxony/unet-pytorch` 的六条核心人工标签，见 `reports/evaluation.md`；真实历史PR回放见 `reports/pytorch-unet-pr-141.md`。

样例内容：

| 路径 | 说明 |
| --- | --- |
| `data\examples\incomplete-ml-project\paper.txt` | 论文正文（TXT，无需 PDF 依赖） |
| `data\examples\incomplete-ml-project\repository\` | 模拟代码仓库，含 `README.md`、`requirements.txt`、`train.py` |
| `data\examples\incomplete-ml-project\expected-findings.json` | 15 条人工预期状态 |

## 1. 演示一：规则模式（命令行，默认）

**操作顺序**

```powershell
python -m src.cli `
  --paper data\examples\incomplete-ml-project\paper.txt `
  --repo data\examples\incomplete-ml-project\repository `
  --output reports\demo-report
```

**输入**：论文路径 + 仓库目录，均为本机路径，不联网、不上传。

**输出**（新增两个文件，**不覆盖** `reports\first-report.*` 与 `reports\verify.*`）：

```text
reports\demo-report.json
reports\demo-report.md
```

**预期观察点**

1. 终端三行输出。第 3 行为统计：

```text
已生成：...\reports\demo-report.json
已生成：...\reports\demo-report.md
检查完成：15 项，6 个高风险，6 项当前范围内未找到。
```

2. 打开 `demo-report.md`，`待修复任务` 章节应有 **10 条**（15 条规则减去 5 条已确认项）。
3. 每条任务带**证据位置**，指向 `论文第 N 页` 或 `文件名:行号`。这是本项目与「论文问答机器人」的核心差别。
4. `missing` 状态的措辞是「当前检查范围内未找到」，不是「不存在」。

**失败降级**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `错误：论文路径不存在` | 路径写错 | 改用绝对路径 |
| `不支持的论文格式` | 扩展名不是 txt/md/pdf | 换格式或换文件 |
| `读取 PDF 需要 pypdf` | 未装依赖 | 装依赖，或改用 TXT 输入 |

退出码：`0` 成功；`2` 输入不可用（错误写入标准错误）。

## 2. 演示二：网页模式

**操作顺序**

```powershell
python -m src.web --host 127.0.0.1 --port 8765
```

浏览器打开 `http://127.0.0.1:8765`。

在首页填写：

| 字段 | 填入 |
| --- | --- |
| 论文路径 | `data\examples\incomplete-ml-project\paper.txt` |
| 代码仓库路径 | `data\examples\incomplete-ml-project\repository` |
| 检查模式 | 规则模式（离线，默认） |

提交后进入结果页。

**输出**：结果页在线展示，另有 JSON / Markdown 两个下载入口。

**预期观察点**

1. 结果页显示统计区与「待修复」清单，条目与命令行版本一致。
2. 网页**只接受本机路径**，不接受文件上传，不连接 GitHub。
3. 用户输入会被 HTML 转义，避免注入（有对应测试）。

**失败降级**

| 现象 | 处理 |
| --- | --- |
| 端口被占用 | 换 `--port 8766` |
| 页面提示路径错误 | 用绝对路径重填 |
| 浏览器打不开 | 确认服务窗口仍在运行，地址为 `127.0.0.1` 而非 `localhost` 以外的地址 |

## 3. 演示三：可选本地开源模型模式

**前提**：本机已安装 Ollama，且已拉取至少一个模型。

```powershell
ollama pull qwen2.5:3b
ollama run qwen2.5:3b
```

模型名可替换为本机已拉取的任意模型。

**操作顺序**

```powershell
python -m src.cli `
  --paper data\examples\incomplete-ml-project\paper.txt `
  --repo data\examples\incomplete-ml-project\repository `
  --output reports\demo-report-model `
  --model-mode ollama --model-name qwen2.5:3b --ollama-url http://127.0.0.1:11434
```

网页模式则把「检查模式」选为「本地开源模型辅助」。

**预期观察点（模型可用时）**

1. 终端多一行 `模型辅助：ollama / <模型名> / 模型可用`。
2. 报告的 `模型辅助结果` 章节出现，并标注**「不替代规则判定」**。
3. 该章节的每条要素都带来源编号（论文行 `P###`、仓库行 `F###`）；引用了清单外编号的条目会被丢弃。
4. **规则部分与演示一逐字段一致**——模型不改变任何一条判定。

**预期观察点（模型不可用时）**

1. 退出码仍为 `0`，报告照常生成，规则结果不受影响。
2. 终端显示：

```text
模型辅助：ollama / qwen2.5:3b / 模型不可用
  <失败原因>。本机未检测到可用的本地模型服务。安装并启动 Ollama 后运行
  `ollama run qwen2.5:3b`，再用 --model-mode ollama 重新检查；
  不安装模型时，规则模式仍可离线使用。
```

3. JSON 报告中 `model_assistance.status` 为 `unavailable`，并附同样的安装提示。

**注意**：模型不可用时**不得**把结果说成 `ok`，也不要用单元测试里的模拟 HTTP 结果冒充真实运行。

## 4. 演示四：真实项目核心规则评测

```powershell
python -m src.evaluation --root data\evaluation
```

**预期观察点**

1. 输出 U-Net 6 条已标注核心规则的逐条对照；另外列出 9 条未标注规则。
2. 当前汇总显示精确状态一致率100%、缺口精确率100%、缺口召回率100%。
3. 同时展示初始基线：R001、R003、R014 原本被误判为 `found`，基线一致率与召回率均为50%；补充完整性判断后，同组复测达到6/6。

**必须同时说明的限制**：这是真实公开项目上的小样本评测，但规则针对同一组失败样本做过改进，且6条人工标签全部为缺口正类。因此6/6只能说明已知失败模式得到修复，不能代表跨项目准确率或评估误报率。

如需展示规则实现的固定回归样例，可另运行：

```powershell
python -m src.evaluation --root data\examples
# 该自造样例的 15/15 一致只用于验证规则自洽，不能作为真实项目准确率。
```

## 6. 失败降级总表

| 演示项 | 失败情形 | 降级方式 |
| --- | --- | --- |
| 规则模式 CLI | 输入路径错误 | 换绝对路径重跑，退出码 2 并给出原因 |
| 规则模式 CLI | PDF 依赖缺失 | 改用 `paper.txt` 演示 |
| 网页模式 | 端口占用 | 换端口 |
| 网页模式 | 服务未启动 | 重新执行启动命令 |
| 模型模式 | Ollama 未装 / 未启动 | 报告标注 `unavailable` 并给出安装提示；规则结果照常输出 |
| 模型模式 | 模型名不存在 | 换成本机 `ollama list` 中已有的模型名 |
| 评测骨架 | 评测集为空 | 退出码 2 并提示；改为指向 `data/examples` 演示规则自洽性 |

共同原则：**任何一部分不可用都不影响规则模式离线出结果**。这也是可演示性的底线。

## 7. 本机实测记录（2026-09-30）

| 项 | 结果 |
| --- | --- |
| 规则模式 CLI | 退出码 `0`，生成 JSON + Markdown，输出「15 项，6 个高风险，6 项当前范围内未找到」 |
| 网页首页 | HTTP `200`，含 `paper` / `repo` / `model_mode` 三个表单字段与两种模式选项 |
| 网页提交 | HTTP `200`，结果页含「待修复」清单、规则编号与下载入口 |
| Ollama 真实可用性 | **不可用** |
| Ollama 复现命令 | `python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:11434/api/tags', timeout=4)"` |
| Ollama 失败原文 | 直接探测：`HTTPError: HTTP Error 502: Bad Gateway`；经程序调用：`无法连接本地模型服务：[WinError 10054] 远程主机强迫关闭了一个现有的连接` |
| 模型模式报告状态 | `model_assistance.status = unavailable`，`findings` 仍为 15 条，退出码 `0` |

结论：规则模式与网页模式可现场演示；本地模型模式在本机当前环境下**无法演示真实调用**，只能演示 `unavailable` 降级路径。
