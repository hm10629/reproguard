# 参赛作品信息

## 作品名称

**ReproGuard复现守门人**

名称共15个字符（按逐字符计数），不超过20字限制。

## 参赛方向建议

建议选择：**（二）AI开发工具与开源协作**。

作品直接作用于开源科研仓库的Pull Request协作环节，形态为GitHub Action、命令行工具和结构化工作流，核心价值是提高科研代码审查与复现证据维护的质量。跨学科协议审查属于扩展能力，不建议改报“综合创新”，以免削弱主线。

## 作品简介（300字以内）

科研代码的普通审查关注语法、风格和安全，却难以判断参数、数据流程或评价方式变更是否破坏论文复现条件。ReproGuard面向开放科研仓库，在GitHub Pull Request阶段读取代码差异，对照论文、实验协议或复现档案，以确定性规则为权威，并允许来源受限的开源模型辅助，生成带代码行号、论文位置、风险类型和人工复核状态的结构化意见。项目回放真实PyTorch-UNet历史PR，提示3项待复核的评价流程风险；同时在U-Net公开项目上完成6条核心规则的人工标注、失败分析和规则改进。成果包括GitHub Action、命令行与网页原型、开放Schema、评测脚本、测试用例及合规文档。

## 一句话介绍

把论文和实验协议中的复现约束带进GitHub PR，让科研代码的每次关键变化都有证据、能复核、可追踪。

## 核心亮点

1. 审查的不是一般代码质量，而是参数、随机性、数据和评价流程变化造成的科研复现风险。
2. 风险同时绑定diff行号和论文/协议来源，模型不能生成无来源结论。
3. 所有科研判断默认等待人工确认，不把AI建议包装成事实。
4. 用真实历史PR和独立人工标注记录“漏报—分析—修复—复测”的完整证据链。
5. 以GitHub复合Action开放，目标是其他仓库通过一行`uses`引用。
