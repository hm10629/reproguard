# ReproGuard 当前实施方案

> 状态日期：2026-10-23<br>
> 本文档是当前产品定位的简版基线；早期“开放科研复现证据链”文档保留为能力来源和历史设计记录。

## 1. 产品定位

ReproGuard 是面向开放科研仓库的 AI 复现变更审查工具。它在 GitHub Pull Request 阶段回答：

> 本次代码或研究材料变化，是否改变了论文、实验协议或复现档案中的关键条件？变更后缺少哪些配置、日志、结果或解释？

它不做通用代码风格审查，也不自动证明论文错误。所有科研判断默认等待维护者确认。

## 2. 当前核心闭环

```text
PR unified diff
      ↓
论文 / 协议 / 复现档案基线
      ↓
确定性变更规则 + 来源受限的开源模型
      ↓
带文件行号、论文页码和修复建议的风险
      ↓
GitHub 注释 + Step Summary + JSON/Markdown
      ↓
维护者人工确认
```

## 3. 当前工程能力

- 解析标准 unified diff，包括带空格的文件路径；
- 保留新增行和删除行的位置；
- 检查学习率、批大小、随机种子、训练轮数、数据集、模型、评价指标等参数变化；
- 检查温度、浓度、时长、阈值、参考基因组等跨学科协议参数；
- 识别随机种子删除、依赖环境变化、数据处理与评价流程变化；
- 在论文或协议中定位旧参数时，将风险升级并附加来源位置；
- 输出 GitHub workflow warning；
- 自动写入 `$GITHUB_STEP_SUMMARY` 和 `$GITHUB_OUTPUT`；
- 模型只可引用真实 diff `D###` 和论文/协议 `P###`，编造引用会被丢弃；
- 规则模式无需模型、API Key 或网络；
- 支持 Ollama 本地开放模型和 DeepSeek/OpenAI 兼容接口；
- `--fail-on` 可配置为只提示、遇高风险失败或遇任意风险失败。

## 4. 跨学科边界

跨学科通过“统一变更证据 + 领域参数词表”实现，不声称模型自动精通所有学科。

| 场景 | 可审查材料 |
| --- | --- |
| 机器学习 | 训练配置、数据处理、指标、随机种子、依赖 |
| 生物信息学 | 参考基因组、流程配置、软件版本、样本元数据 |
| 实验协议 | 温度、浓度、时长、阈值、步骤说明 |
| 社会科学 | 数据清洗、变量编码、排除规则、统计脚本 |

当前只检查 Git 可见的数字材料。真实实验是否发生、测量是否准确、领域变化是否合理，必须由研究人员确认。
