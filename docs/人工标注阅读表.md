> **非可信输入**：本表不替代论文与仓库原文；标注必须回到原文判定。

## 0. 标注口径与红线

- 每条标注**只能**填下列五值之一：`found` / `partial` / `missing` / `not_applicable` / `needs_review`。
- 判定口径以 `docs/检查规则-v0.1.md` 为准：

  | 状态 | 含义 |
  | --- | --- |
  | `found` | 存在明确、可定位的证据，信息足以支持下一步复现 |
  | `partial` | 只找到部分信息（例如说了用哪个数据集，但没给版本或划分方式） |
  | `missing` | 在当前检查范围内没有找到 |
  | `not_applicable` | 该规则不适用于当前项目 |
  | `needs_review` | 发现了可能相关的材料，但无法可靠判断 |

- **不得参考工具输出（`报告` / `reports/` / 任何 JSON）反推标注**。先读原文，独立判定，最后才可与工具结果比对差异。
- `missing` 不等于「不存在」，表述应为「在当前检查范围内未找到」。
- 每条建议记录依据：论文页码 / 文件行号 / 章节。
- 标注完成后，由人把 `annotation-template.json` 改名为 `expected-findings.json`（**本表不代为改名**）。

## 5. 填写格式

逐条记录形式（便于附依据）：

```json
{
  "expectations": [
    {"rule_id": "R001", "expected": "found", "note": "README 第 3 行说明项目用途"},
    {"rule_id": "R002", "expected": "missing", "note": "顶层无 requirements.txt，README 未列依赖版本"}
  ]
}
```

同时记录 `annotated_by`（可留空，但须说明依据）与 `annotated_at`。

约束（由 `data/evaluation/schema.json` 与 `src/evaluation.py` 强制）：

- `rule_id` 必须匹配 `^R[0-9]{3}$`，例如 `R005`；
- `expected` 必须是五值之一；
- 不允许重复 `rule_id`；`expectations` 不得为空。

## 6. 红线复述

1. **不得参考工具输出反推**标注。
2. **不得预填状态**，也不得用占位值假装已完成。
3. **不得给出任何指标数字**（一致率、精确率、召回率等）。
4. 改名为 `expected-findings.json` 的动作**由人执行**，不由工具代办。
