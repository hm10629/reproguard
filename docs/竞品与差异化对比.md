# ReproGuard 竞品与差异化对比

> 核验日期：2026-10-22。只比较各工具官方文档明确声明的核心用途，不推断其未公开能力。

## 结论

ReproGuard 不替代普通代码审查、安全扫描或依赖漏洞告警。它补充的是一个更窄的环节：**当科研仓库的 PR 改变实验参数、数据/评价流程或环境时，把代码差异与论文、实验协议和复现档案中的约束对应起来，并生成带 diff 行号、来源位置和人工复核状态的风险记录。**

## 功能对比

| 功能点 | GitHub Pull Request Review | Dependabot Alerts | CodeQL Code Scanning | ReproGuard |
| --- | --- | --- | --- | --- |
| 对代码 diff 进行人工讨论与批准 | 是 | 否 | 否 | 输出供维护者确认的辅助意见 |
| 发现已知脆弱依赖 | 否 | 是 | 部分安全查询覆盖 | 否 |
| 静态分析安全漏洞和代码缺陷 | 否 | 否 | 是 | 否 |
| 识别科研参数、随机种子和评价流程变化 | 依赖审查者经验 | 否 | 非核心目标 | 是 |
| 对照论文/协议中的旧值或研究约束 | 无专用结构 | 否 | 否 | 是 |
| 输出论文页码/协议来源与 diff 行号 | 无专用结构 | 否 | 否 | 是 |
| 把不确定结论标为人工复核而非自动裁决 | 可由审查者讨论 | 告警处置 | 告警处置 | 是，默认 `needs_human_review` |
| 建立可导出的复现档案和规则评测记录 | 否 | 否 | 否 | 是 |

## 创新边界

- 创新点不是“用 AI 审代码”，而是把**研究约束—PR 差异—复现风险—人工确认**做成可追溯闭环。
- 确定性规则负责稳定、可解释的结构化检查；模型仅补充科研语义提示，并受来源编号白名单约束。
- 当前证据只覆盖一个真实历史 PR 和一个真实项目的 6 条核心标注，不能声称已全面优于现有工具。
