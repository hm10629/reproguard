# ReproGuard答辩PPT结构

建议10页，控制在5分钟内讲完。每页只保留一个结论，避免展示大段代码。

## 第1页：标题

- ReproGuard复现守门人
- 副标题：把科研复现约束带进GitHub Pull Request
- 团队、学校、指导教师 `【必须人工补充】`

讲述重点：普通审查问“代码能不能合并”，ReproGuard增加一个问题——“合并后论文实验还能按原条件复现吗？”

## 第2页：真实痛点

- 参数、数据和评价流程持续随PR变化；
- 论文、代码、实验结果之间容易失去同步；
- 通用审查、安全扫描和依赖告警没有专门表示科研约束。

视觉建议：左侧论文实验条件，右侧PR diff，中间一个断裂的对应关系。

## 第3页：解决方案

展示六步流程：PR diff → 论文/协议 → 规则+AI → 来源约束 → GitHub意见 → 人工确认。

一句话：不是让AI自动裁决科研正确性，而是把可能改变复现口径的变化连同证据提前交给维护者。

## 第4页：核心创新

- 研究约束与代码变化对齐；
- diff行号与论文来源双证据；
- 模型来源白名单与规则权限隔离；
- 人工复核状态和可导出复现档案；
- 从真实漏报驱动规则迭代。

## 答辩高频问题准备

### 这不就是AI代码审查吗？

通用代码审查关注bug、风格或安全。本项目的核心对象是论文/协议中的研究约束，并要求每条科研风险同时绑定变更行和来源位置。

### 为什么需要AI，规则不够吗？

明确的参数和结构变化由规则稳定处理；跨学科同义概念和非结构化步骤由模型辅助。模型没有最终裁决权，且引用受白名单限制。

### 6/6是否说明准确率100%？

不能。它是同一组已知失败样本上的修复复测，且无负类。报告明确保留基线、改进过程和泛化限制。

### 跨学科如何实现？

通过统一证据模型、协议参数Schema和Git可见材料，而不是声称一个模型自动精通所有学科。当前成熟演示仍聚焦代码复现。

### 你们自主做了什么？

PR解析、科研参数规范、确定性规则、论文约束对齐、来源白名单、人工复核流程、报告、Action、网页、评测和测试均为团队自主实现；第三方资源及许可证单独披露。
